# Обоснование НМЦД

Сервис по описанию закупки находит цены сопоставимых товаров в открытых источниках, сверяет их с ТЗ
по существенным характеристикам, приводит к единице закупки, отсекает аномалии и формирует обоснование
начальной (максимальной) цены договора методом сопоставимых рыночных цен. У каждой цены в отчёте есть
источник, дата получения, сохранённая копия страницы и объяснение, почему она вошла в расчёт или исключена.

На вход — ТЗ в DOCX, PDF или текст. На выходе:

1. список найденных предложений с названием источника и ссылкой;
2. характеристики каждого предложения со статусом сверки с ТЗ («совпадает», «нет данных», «не совпадает»);
3. цена и единица измерения, приведённые к единице закупки, с шагами приведения;
4. класс сопоставимости (идентичное, однородное, неподходящее) и релевантность;
5. список исключённых предложений с причиной (выброс, несопоставимые характеристики, другая единица, нет данных);
6. расчёт: среднее, медиана, минимум и максимум, коэффициент вариации, НМЦД позиции и итог;
7. отчёт, в котором виден весь путь от ТЗ до цены: HTML, документ обоснования DOCX, расчёт XLSX с формулами
   (пересчитывается в Excel), JSON с журналом шагов.

Если надёжных цен меньше трёх или разброс выше 33 %, цена не формируется: отчёт объясняет причину,
показывает, какие цены сильнее всего влияют на разброс, и готовит запрос коммерческих предложений.

Сайт решения с готовыми расчётами по ТЗ кейса, видео и презентацией — https://annakrutiwka2026-a11y.github.io/nmcd-analyst/ . Презентация — [presentation/nmcd_presentation.pdf](presentation/nmcd_presentation.pdf), видео работы сервиса — [presentation/nmcd_demo.mp4](presentation/nmcd_demo.mp4).

## Быстрый старт

Нужен Docker с Compose v2.

```bash
docker compose up -d --build
```

Ключи в репозиторий не входят. Без них сервис работает: техническое задание разбирается по правилам, цены
берутся из реестра контрактов ЕИС. Чтобы подключить модель и поиск по сайтам поставщиков, скопируйте шаблон
(`cp .env.example .env`), впишите ключи и выполните `docker compose up -d` ещё раз (см. «Переменные окружения»).
Как поднять общедоступный стенд с HTTPS — [deploy/README.md](deploy/README.md).

Откройте http://localhost:8000, загрузите ТЗ или вставьте описание закупки текстом. У каждого примера на главной
странице есть ссылка «Открыть отчёт» — готовый отчёт, посчитанный заранее в полном режиме; его можно открыть сразу,
не дожидаясь расчёта. Отчёты тех же примеров без ключей лежат в `examples/reports_no_keys/`.
Первый расчёт одного ТЗ занимает 1–3 минуты (запросы к ЕИС идут с паузами, чтобы не нагружать сайт); повторный
расчёт того же ТЗ берёт ответы источников из кеша и занимает секунды.

Остановка: `docker compose down` (результаты сохраняются в томе `nmcd-data`).
Полная очистка вместе с результатами: `docker compose down -v`.

Расчёт из командной строки внутри контейнера:

```bash
docker compose run --rm nmcd python -m app.cli analyze examples/tz/tz_paper.docx --out /data/out/paper
```

Тесты:

```bash
docker compose run --rm nmcd python -m pytest -q
```

Без Docker: Python 3.12+, `pip install -r requirements-dev.txt`, затем
`uvicorn app.web.main:app --port 8000` или `python -m app.cli analyze <файл>`.

## Режимы работы

| Режим | Что нужно | Что уходит наружу | Что получается |
|---|---|---|---|
| Без ключей | ничего | поисковые запросы к ЕИС | разбор ТЗ по правилам, цены исполненных контрактов ЕИС |
| Контур заказчика | ключ Яндекс Search API, `NMCD_DISABLE_LLM=1` | поисковые запросы к ЕИС и поисковому API | плюс цены интернет-магазинов и дистрибьюторов; ТЗ не покидает сервер |
| Полный | ключи модели и поискового API | плюс обезличенный текст ТЗ и тексты публичных страниц | модель уточняет карточку ТЗ и сопоставляет характеристики страниц с ТЗ |

Во всех режимах расчёт, отбор, выбросы и формула одинаковые: модель не считает цену и не принимает решение
о включении цены, она только выписывает значения характеристик с цитатами, которые затем сверяются с текстом
источника.

## Требования к окружению

| Ресурс | Значение |
|---|---|
| ОС | любая с Docker 24+ и Compose v2 (Linux, macOS, Windows) |
| CPU / память | 1 vCPU, 1 ГБ RAM |
| Диск | ~0,5 ГБ под образ, кеш и копии страниц растут по мере работы (сотни КБ на расчёт) |
| Сеть | исходящий HTTPS к zakupki.gov.ru; при наличии ключей — к поисковому API и API модели |

Зависимости (точные версии — `requirements.txt`): FastAPI и Uvicorn (веб), httpx (HTTP-клиент), lxml (разбор
страниц), python-docx, openpyxl, pypdf (документы), pydantic (модели данных), anthropic (клиент модели), PyYAML.

## Переменные окружения

Все необязательны. Без ключей сервис работает: разбор ТЗ и сверка — по правилам, цены — из ЕИС.

| Переменная | Назначение |
|---|---|
| `LLM_API_KEY` | ключ Anthropic-совместимого API модели; включает разбор ТЗ и сверку характеристик моделью |
| `LLM_BASE_URL` | адрес API модели, если это не api.anthropic.com (корпоративный шлюз) |
| `LLM_MODEL` | модель, по умолчанию `claude-sonnet-5` |
| `LLM_MAX_TOKENS_PER_RUN` | предел токенов на один расчёт (600 000) |
| `YANDEX_SEARCH_API_KEY`, `YANDEX_FOLDER_ID` | ключ и каталог Яндекс Search API v2 — поиск предложений на сайтах поставщиков |
| `NMCD_ORG_NAME` | организация для свойств и шапки документов |
| `NMCD_CONTACT_URL` | контактный адрес организации для User-Agent при обращении к сайтам (необязательно) |
| `NMCD_PORT` | порт веб-интерфейса на хосте (8000) |
| `NMCD_DISABLE_LLM`, `NMCD_DISABLE_WEB` | `1` — выключить модель или веб-поиск, даже если ключи заданы |
| `NMCD_PUBLIC` | `1` — общедоступный стенд: на главной каждый видит только свои расчёты |
| `NMCD_MAX_QUEUE` | сколько расчётов может ждать и идти одновременно (6); сверх этого — «Сервис занят» |
| `LLM_DAILY_TOKEN_BUDGET` | предел токенов модели в сутки на весь сервис (0 — без предела); после него расчёт идёт по правилам |

## Внешние сервисы

| Сервис | Для чего | Ключ |
|---|---|---|
| ЕИС, zakupki.gov.ru | реестр контрактов: исполненные контракты за 3 года, позиции, цены за единицу, поставщики | не нужен |
| Яндекс Search API v2 | поиск страниц поставщиков и интернет-магазинов | `YANDEX_SEARCH_API_KEY` |
| API языковой модели | разбор ТЗ и характеристик предложений; получает только обезличенные тексты | `LLM_API_KEY` |
| Росстат | индекс потребительских цен для старых цен; файл уже в образе, обновление `python tools/update_cpi.py` | не нужен |

Подробно об источниках, в том числе о тех, что не используются из-за антибот-защиты или запрета в robots.txt, —
[docs/SOURCES.md](docs/SOURCES.md).

## Как это работает

```
ТЗ → карточка закупки → поиск (ЕИС, сайты) → характеристики предложений → сверка → приведение цены
   → отбор, выбросы, разброс → расчёт НМЦД → отчёт (HTML, DOCX, XLSX, JSON)
```

1. **Карточка.** ТЗ читается вместе с таблицами. Разбор по правилам находит позиции, количество, единицы, ОКПД2,
   характеристики с условиями («не менее», «от … до», «± допуск»), содержимое единицы (500 листов, не менее 10 мкг).
   Если подключена модель, она уточняет карточку: отмечает существенные характеристики, составляет поисковые фразы.
   Каждая характеристика хранит цитату из ТЗ.
2. **Поиск.** В реестре ЕИС берутся только исполненные контракты за 3 года; из карточки контракта — позиции
   с ценой за единицу, КТРУ/ОКПД2, полный список характеристик, поставщик и ИНН. Через поисковый API находятся
   страницы поставщиков; цена берётся из разметки schema.org или из текста.
3. **Сверка.** Значения характеристик предложения выписываются с цитатой из источника и сравниваются
   с требованиями ТЗ с учётом единиц, допусков и границ («≥ 160 и < 180 г/м²»). Модель указывается точно:
   «D600 Pro 2 HS» — другая модификация. Итог — идентичное, однородное или неподходящее.
4. **Приведение.** Цена переводится в единицу закупки (цена пачки из цены коробки, 500 листов из 250 листов,
   цена за 1 мкг из реестра — на фасовку по ТЗ), учитываются НДС, доставка, ступени цены; цены старше полугода
   приводятся по ИПЦ Росстата. Фасовка реактивов, отличная от ТЗ больше чем в 2 раза, не пересчитывается.
5. **Отбор и расчёт.** Правовые фильтры (по ЕИС проверяются неустойки по контракту и запись поставщика
   в реестре недобросовестных поставщиков), дубли, выбросы по медиане и MAD, коэффициент вариации,
   формула п. 3.21.
6. **Отчёт и решения специалиста.** Специалист может исключить или вернуть любую цену с указанием причины —
   расчёт пересчитывается сразу, решение записывается в журнал. Если цен мало, сервис готовит запрос коммерческих
   предложений с возможными адресатами; полученные ответы вносятся в отчёт формой «Добавить цену из коммерческого
   предложения» (цена за единицу с доставкой, дата, поставщик, ИНН с проверкой контрольной суммы) — и цена
   пересчитывается по тем же правилам. В документе обоснования КП указываются без наименований поставщиков
   (п. 2.1 Методических рекомендаций).

Архитектура и компоненты — [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md). Методика и правила с основаниями —
[docs/METHOD.md](docs/METHOD.md). Примеры с входом и результатом — [docs/USE_CASES.md](docs/USE_CASES.md).

## Настройка без правки кода

| Файл | Что настраивается |
|---|---|
| `config/rules.yaml` | формула (среднее, медиана, минимум), число поставщиков, порог разброса, срок давности, правила выбросов, допуск «идентичного» |
| `config/sources.yaml` | источники, паузы между запросами, лимиты, домены, которые не запрашиваются |
| `config/privacy.yaml` | наименования и адреса заказчика, которые не уходят во внешнюю модель |

## Проверяемость

- У каждой цены — ссылка на источник, дата и время получения, сохранённая копия страницы с SHA-256.
- У каждой характеристики — цитата из источника; цитата сверяется с текстом источника автоматически.
- XLSX содержит формулы: среднее, стандартное отклонение, коэффициент вариации и НМЦД пересчитываются в Excel.
- JSON содержит весь расчёт: карточку, предложения, решения, журнал шагов, параметры правил.

## Защита данных

Во внешние API передаются только открытые данные. Перед вызовом модели ТЗ проходит обезличивание:
наименование и адреса заказчика, ФИО, телефоны, e-mail, ИНН и другие реквизиты, суммы и даты заменяются метками.
В отчёте видно, сколько сведений скрыто и какой текст ушёл в модель. Без ключа модели наружу уходят только
поисковые запросы.

## Ограничения

- ЕАТ «Берёзка», Портал поставщиков, ГИСП, Ozon, Яндекс Маркет, ВсеИнструменты не опрашиваются: они закрыты
  антибот-защитой или запретом в robots.txt, обход защиты сервис не выполняет.
- Реестр договоров по 223-ФЗ пока не подключён: используются контракты 44-ФЗ.
- Цены интернет-магазинов розничные; для оптовых объёмов они дают верхнюю оценку.
- Страницы, которые формируются только скриптом в браузере, пропускаются с пометкой в журнале.

## Структура

```
app/            код сервиса (ingest, sources, llm, engine, report, web, cli)
config/         правила, источники, список скрываемых сведений
data/           сертификаты Минцифры для сайтов госорганов, ряд ИПЦ Росстата
deploy/         общедоступный стенд: HTTPS через Caddy, временный адрес через туннель
docs/           архитектура, методика, источники, примеры
presentation/   презентация решения (PDF, PPTX) и видео работы сервиса
examples/       ТЗ (три из материалов кейса и одно текстовое описание), готовые отчёты в полном режиме (reports)
                и без ключей (reports_no_keys), копии страниц-источников к ним (evidence)
tests/          тесты ядра, разбора и источников (на сохранённых страницах, без сети)
tools/          обновление ИПЦ, сборка описания примеров (USE_CASES.md), копии страниц к примерам, сайт с готовыми
                расчётами (build_site.py)
```
