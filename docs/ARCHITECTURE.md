# Архитектура

Один сервис на Python (FastAPI) без внешней базы данных: всё состояние расчёта хранится в файлах на томе `/data`.
Это упрощает развёртывание и делает каждый расчёт воспроизводимым: отчёт JSON содержит все входные данные,
промежуточные результаты и журнал шагов.

## Поток данных

```
 ТЗ (DOCX/PDF/TXT) или текст
        │
        ▼
 1. Чтение документа ─────────── app/ingest/reader.py      абзацы и таблицы в исходном порядке
        │
        ▼
 2. Карточка закупки ─────────── app/ingest/rules_parser.py разбор по правилам (всегда); существенные
        │                                                   характеристики — по общему списку config/rules.yaml
        │                        app/llm/redact.py          обезличивание перед внешней моделью
        │                        app/llm/client.py + prompts уточнение моделью (если есть ключ)
        ▼
 3. Поиск предложений ────────── app/sources/eis.py        реестр контрактов ЕИС: исполненные контракты, позиции,
        │                                                   цена за единицу, КТРУ/ОКПД2, поставщик и ИНН
        │                        app/sources/web.py        Яндекс Search API → страницы поставщиков → schema.org
        │                        app/sources/http.py       robots.txt, паузы, повторы, кеш, копии страниц (SHA-256)
        ▼
 4. Извлечение характеристик ─── app/pipeline.py (extract) характеристики реестра (КТРУ) и таблиц карточки
        │                                                   товара; модель сопоставляет их с ТЗ и выписывает
        │                                                   значения из текста с цитатами, цитаты сверяются
        ▼
 5. Сверка ───────────────────── app/engine/matching.py    идентичное / однородное / неподходящее по существенным
        │                                                   характеристикам, проверка каждой характеристики
        ▼
 6. Приведение цены ──────────── app/engine/normalize.py   единица, содержимое упаковки, НДС, доставка, ступени
        │                        app/engine/cpi.py          цены, ИПЦ Росстата для цен старше полугода
        ▼
 7. Отбор и расчёт ───────────── app/engine/selection.py   правовые фильтры, дубли, выбросы (медиана и MAD),
        │                                                   коэффициент вариации, формула п. 3.21;
        │                        app/pipeline.py           неустойки по контрактам и РНП проверяются в ЕИС
        ▼
 8. Отчёт ────────────────────── app/report/*              HTML, DOCX (форма обоснования), XLSX (формулы), JSON
```

Все параметры правил — в `config/rules.yaml`, источники — в `config/sources.yaml`, список скрываемых сведений
о заказчике — в `config/privacy.yaml`. Логика при их изменении не правится.

## Компоненты

| Модуль | Назначение |
|---|---|
| `app/models.py` | Модели данных: позиция, требование, предложение, сверка, приведение, решение, расчёт, отчёт |
| `app/ingest/` | Чтение DOCX/PDF/TXT; разбор типовой формы ТЗ (таблица позиций, таблица характеристик, условия поставки) |
| `app/llm/` | Клиент модели (строгий JSON через вызов инструмента, кеш, лимит токенов), промты, шлюз обезличивания |
| `app/sources/` | HTTP-клиент с robots.txt и защитой от перегрузки сайтов; источники ЕИС и сайтов поставщиков |
| `app/engine/` | Вычислительное ядро без сети: единицы, сверка, приведение, ИПЦ, отбор, выбросы, расчёт |
| `app/pipeline.py` | Оркестрация шагов, журнал, пересчёт по решениям специалиста |
| `app/report/` | HTML-отчёт, DOCX-обоснование, XLSX с формулами, JSON |
| `app/web/` | Веб-интерфейс: загрузка, ход расчёта (SSE), отчёт, «Исключить/Вернуть», выгрузки |
| `app/cli.py` | Расчёт из командной строки |
| `tools/update_cpi.py` | Обновление ряда ИПЦ из официального файла Росстата |

## Надёжность

- У каждого запроса таймаут, до двух повторов с паузой, общий темп для одного сайта (ЕИС — не чаще раза в 0,6 с).
- Запрос к модели повторяется при перегрузке и сетевом сбое (паузы 3, 8, 20 с); если пакет предложений не разобран,
  он делится пополам и отправляется снова. Что модель так и не разобрала, сверяется по правилам — с записью
  в журнале.
- Нестандартная страница или сбой на одной позиции не останавливают расчёт: страница пропускается с причиной,
  позиция получает статус «цена не сформирована» с пояснением, остальные позиции считаются.
- Перед загрузкой страницы проверяется robots.txt. Если сайт отвечает капчей или 401/403, он пропускается до конца
  расчёта, а в отчёте указана причина. Защита сайтов не обходится, User-Agent честный.
- Ответы сайтов и модели кешируются (24 часа для страниц), повторный расчёт не нагружает источники.
- Упавший источник не останавливает расчёт: позиция считается по оставшимся, состояние источников видно в отчёте.
- Если данных мало, цена не формируется: отчёт объясняет причину и подсказывает, что сделать.
- Сбой на любом шаге не теряет отчёт: он сохраняется со статусом ошибки и журналом.

## Защита данных

Во внешние API уходят только открытые данные. Перед вызовом модели текст ТЗ проходит шлюз обезличивания:
наименование и адреса заказчика, ФИО, телефоны, e-mail, ИНН и другие реквизиты, суммы и даты заменяются метками,
технические характеристики остаются. Тексты страниц поставщиков тоже очищаются от телефонов, e-mail и ИНН (ИНН
продавца извлекается локально). Без ключа модели сервис не передаёт наружу ничего, кроме поисковых запросов
к ЕИС и поисковому API.
